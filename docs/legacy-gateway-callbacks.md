# Mapay and Coinbase legacy callbacks

Mapay now records the authenticated provider pay_no instead of its pay_id (shop order number). Previously two differently paid callbacks for one shop order reached completedOrder with the same shop number as trade_no and appeared to be one provider transaction. The native route regression reproduced that stored value before the fix. Duplicate same-transaction callbacks still fulfill once; a different provider transaction after completion returns fail.

Coinbase now authenticates the current Request body/header and selects a sufficient confirmed/resolved CNY payment explicitly. It no longer uses php://input or process-global headers, nor the last loop variable. The previous native route returned500 in the isolated request context; independent execution of the old loop also reproduced a sufficient confirmed payment followed by pending being rejected solely because it was last. Reordered pending/confirmed and resolved/overpaid cases now run actual fulfillment. Single sufficient payment and charge code remain the old contract; multiple partial payments are not added together. The local receipt amount remains a decimal string, with a128-byte budget, at most80 integer/fractional digits and exact BCMath comparison. This preserves high-precision positive fee amounts and extra trailing zeros without admitting exponent/negative/undersufficient values.

## Existing request protocols

Mapay retains mqq/type2, mzfb/type1 and mwx/type3, original ID/order/param/URL/timeout/charset fields, sorted raw key=value plus key MD5, and URL-encoded redirect parameters to the configured HTTP/HTTPS endpoint. Price is an exact CNY decimal string. The original PHP7.4 helper omitted integer act/pay_type0 before generating both the query and signature; new code preserves that omission on PHP8.2 while keeping callback string0 signed. Actual PHP7.4 helper create and callback golden signatures are checked in addition to an independent oracle. Configured query prefixes and opaque values are preserved. Empty or populated URL fragments are rejected explicitly because PHP7.4 parse_url does not expose an empty trailing fragment the same way as PHP8.2.

Mapay callbacks parse the current bounded original form body through FormNotification before verifying all received flat fields. Duplicate/encoded duplicate/array/directive fields fail; original whitespace, plus, CRLF and empty values keep their signed bytes. The credential ID must match when echoed; type and param must match the selected mode when echoed. Existing merchant_id/key/pem map to numeric ID, configured endpoint and communication key. Existing route/mode names and success/fail acknowledgements remain.

Coinbase create remains an explicit JSON POST to https://api.commerce.coinbase.com/charges with X-CC-Api-Key and version2018-03-22, original fixed_price/CNY metadata and return/cancel fields. Base price and positive fee multiplication use BCMath; nonpositive fees still mean no markup. Fee digits are retained rather than silently rounding to cents. TLS verification, connect3/total10/read10-second bounds, closed64KiB response streams and no redirects/automatic POST replay are explicit; foreign Guzzle defaults do not override the request. Valid200/201 responses accept HTTPS commerce.coinbase.com /charges/code and /pay/UUID payment pages, with URL/userinfo/port/fragment/control boundaries. The same bounded raw webhook body is HMAC-SHA256 verified with constant-time comparison before payment processing; no new event type/timestamp requirement replaces the old event.data schema. Response acknowledgements stay the old JSON status200 string or fail.

## Locked receipts and actual verification

Both callbacks use current order-selected merchant records, including an already-paid disabled gateway, and the common receiptGuard inside the existing order/card/sales transaction. The guard now also rechecks pay_check alongside order number, price, gateway ID, handler and three merchant fields. Enabled Stripe/PayPal durable bindings remain enforced. Expired paid orders enter the existing manual/abnormal flow without consuming released stock. No new unique charge creation object, webhook inbox, refund or automated reconciliation is introduced in these legacy modes.

GatewayTransactionFixture shares only the real table definitions and instrumented OrderProcessService between CNY and new legacy route suites. Actual payment verification, Eloquent lookups, stock/card/sales mutation and locked completion run; the notification method is replaced. I/O at checkout is a local Guzzle substitute and asserts transaction level0.
