# 后台表单填写指南与改进记录

支付服务由当前 checkout 路由及各支付处理器核对，表单自动映射处理路由和方式标识。选择服务后按“选择服务 → 填写账户 → 保存与启用”填写；保持停用可保存未完成账户，启用时检查必需资料。这里的回调地址仅帮助配置，保存本身不会发起支付。

| 支付服务 | 当前内置付款方式 | 填写重点 |
| --- | --- | --- |
| 支付宝 | 当面付/扫码、电脑网站、手机网站 | AppID、支付宝公钥、应用私钥 |
| 微信支付 | 微信扫码 | AppID、商户号、API V2 密钥 |
| 码支付 | 支付宝、微信、QQ | 商户 ID、服务地址、签名密钥 |
| PaysApi | 支付宝、微信 | UID、签名密钥；中间字段可空 |
| Payjs | 微信扫码 | mchid、通讯密钥 |
| 易支付 | 支付宝、微信、QQ | PID、完整提交地址、MD5 密钥 |
| PayPal | PayPal | Client ID、Client Secret；V2 另需 Merchant ID |
| V免签 | 支付宝、微信 | 通讯密钥、服务根地址 |
| Stripe | Stripe，可保留扩展方式 | Publishable Key、服务端 Key；对账需 Webhook Secret |
| Coinbase | Coinbase | 手续费比例、API Key、Webhook Shared Secret |
| Epusdt | USDT | 签名密钥、完整交易创建地址 |
| BEpusdt | 默认 USDT/TRC20，可输入扩展标识 | AUTH_TOKEN、服务根地址或创建地址 |
| TokenPay | 默认 USDT/TRC20、TRX、ETH，可输入扩展标识 | Currency、签名密钥、服务根地址；标识须以 tokenpay- 开头 |

Stripe 和 PayPal 的运行模式、对账开关及独立 webhook 参数继续遵循运行配置；向导会说明当前模式与该渠道回调路径。历史自定义路由/标识在编辑时保留，未知格式不会自动替换；新增标准服务与付款方式须匹配，付款方式标识全局唯一。

商品按“基本信息 → 发货与库存 → 优惠与买家资料 → 更多设置”填写。搜索简介、关键词留空使用商品名称。自动发货库存来自可售卡密，人工发货填写可售库存。批发优惠按价格档填写，数量为正整数，单价大于零且不高于实际售价；降低售价时也检查已有价格档。买家填写项只在人工处理中使用，填显示名称即可自动生成内部标识。

逐行编辑器保留手动原文入口。错误草稿会保留最近有效配置并阻止提交；未编辑的历史配置保留原内容及换行，新编辑文本会移除空行并转换为运行时所需换行。

| 其他表单 | 填写提示和约束 |
| --- | --- |
| 系统设置 | 邮件驱动及加密方式可选；587/TLS、465/SSL示例；密码和令牌留空保留原值，不回填原文；推送或极验启用时需配套参数 |
| 卡密导入 | 每行一条，粘贴优先；去重仅限本批；单条 0 有效，目标需存在且为自动发货商品 |
| 卡密编辑 | 提示循环出售的真实含义，多行内容仍是一条卡密 |
| 优惠券 | 金额为固定减免，次数为剩余可用次数；说明商品关联和停用方式，保留清空关联 |
| 商品分类 | 名称必填，排序越大越靠前 |
| 邮件模板 | 使用场景可选，可新增自定义标识；新标识唯一，编辑保留锁定；提示单花括号占位变量 |
| 订单编辑 | 提示人工订单状态变更的邮件影响，保存前确认 |
| 邮件测试 | 邮箱格式检查，说明先保存设置，错误返回可读提示 |

保留原 Dcat 登录、权限、字段、保存入口及事务行为。Vue 仅增强填写指导，复用现有 PJAX 生命周期。后台构建命令：

```sh
cd frontend
npm run typecheck:admin
npm test
npm run build:admin
```

HTTP 行为回归位于 tests/Feature/AdminGuidedFormTest.php 与 AdminImportTest.php；前端回归位于 frontend/src/admin/form-guide.test.ts；独立浏览器验收为 tests/browser-admin-guided-forms.cjs，使用 tests/admin-fixture.php --forms 初始化的 8202 合成数据库。验证记录和截图位于 tests/.runtime/forms57/，不含实际商户资料。
