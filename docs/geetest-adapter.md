# 极验V3适配层

旧germey/geetest 3.1.0的清单限制PHP ^7.3、Illuminate 5.5/6/7。本轮将实际依赖与锁文件中的此包移除，改用应用内Guzzle协议客户端及服务提供者，为新框架迁移解除这项限制。当前应用仍为Laravel6，完整框架切换尚未进行。

## 兼容行为

保留 `/check-geetest` 和旧 `/geetest` 别名、gt/success/challenge/new_captcha初始化字段、三个geetest_*提交字段、下单的geetest规则、全局Geetest门面和现有已发布模板命名空间/define指令。旧V3 SDK协议保持php_3.0.0：初始化原始32位challenge与私钥组合后MD5；二次验证先检查 `md5(key + "geetest" + challenge)`，再请求远端并严格匹配返回seccode与提交值的MD5。原V3离线降级公式保留。没有切换至3.1或V4账户协议。

协议根据原已安装SDK核对，并参考[官方V3服务端API](https://docs.geetest.com/captcha/apirefer/api/server)、[官方PHP SDK](https://github.com/GeeTeam/gt3-php-sdk)。在线请求固定HTTPS，TLS校验开启，无重定向，连接3秒/总5秒超时。初始化超时/坏响应生成随机降级challenge；在线验证异常或非成功应答返回校验失败。不会在二次在线验证失败后切到离线通过。请求上下文白名单为user_id/client_type/ip_address，调用方参数不得覆盖协议字段。

## 会话与配置

每次初始化保存服务器发出的随机前缀、当时服务状态、上下文、时间及配置指纹；校验必须匹配当前会话前缀和配置，5分钟内有效。在线V3 challenge带客户端后缀，因此绑定最初32位随机前缀；后缀限制为字母数字且总长度最多64。新初始化覆盖旧挑战；任何实际校验尝试从会话移除状态，顺序重放失败。缺少初始化、缺少凭据、数组字段、超时挑战或其他会话前缀均失败且不会调用远端验证。

这证明会话内顺序消费，不证明跨请求/跨节点的原子一次性消费；Laravel会话的并行请求锁和缓存机制仍取决于部署。原离线降级能力仅作为原V3协议兼容行为保留，未宣称与在线远端校验具有同等验证能力。校验失败后需重新完成验证码。

服务每次构建协议客户端时读取当前配置，长运行服务不保留旧密钥。DujiaoBoot现在合并geetest配置，去除错误的mail配置合并和重复注册。设置页字段、前端主题和业务开关保留原约定。

## 验证

新增7个协议单元用例和12个特性用例；Guzzle MockHandler覆盖握手、原SDK签名、提交表单、白名单/网络选项、超时/坏HTTP/JSON及降级。特性测试经过实际验证码路由与OrderService下单校验，覆盖顺序重放、会话/期限/配置绑定、重新初始化、数组字段、缺少凭据、关闭开关和离线降级。

PHP7.4.33完整107 tests /706 assertions通过；独立协议客户端在系统PHP8.2.31下7 tests /36 assertions通过。PHP7.4实际依赖平台检查、Composer清单/锁文件校验及优化自动加载通过。未访问真实极验服务或使用真实id/key；浏览器中真实供应商组件交互未实测。应用在PHP8.2下的全量启动仍由Laravel6阻挡，本轮仅证明独立客户端兼容。
