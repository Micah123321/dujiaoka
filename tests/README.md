## Expiry recovery

Order creation commits before dispatching the delayed expiry job. Early execution (including the sync queue) leaves the order unpaid until its deadline. `php artisan orders:expire` recovers overdue unpaid orders when queue dispatch fails; the console schedule runs it every minute. Production must run Laravel `schedule:run` every minute using its existing scheduler, in addition to queue workers. This change does not configure the host scheduler automatically.

The recovery sweep uses the current `order_expire_time` setting (minimum one minute); queued new jobs carry their original deadline. Changing that setting while orders are pending can therefore affect recovery timing. A persisted per-order deadline is a later schema migration consideration.

Tests cover actual synchronous queue completion, committed orders surviving dispatch failure, early expiry, overdue-only recovery, and rollback on exhausted coupons. Error log lines containing `Injected queue failure` or `Injected notification failure` are expected fault-injection outputs.
