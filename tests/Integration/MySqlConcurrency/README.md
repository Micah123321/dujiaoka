# Isolated MySQL concurrency acceptance

Run each dependency tree sequentially against the existing isolated MySQL instance:

~~~powershell
& tests/.runtime/php74/php.exe -c tests/.runtime/mysql-fixture-php.ini tests/Integration/MySqlConcurrency/run.php --enable-isolated-mysql
& tests/.runtime/php85/php.exe -c tests/.runtime/php85-fixture.ini tests/Integration/MySqlConcurrency/run.php --enable-isolated-mysql --candidate
~~~

Install the independent legacy dependencies first with `composer install --working-dir=tests/Compatibility/Laravel6 --no-scripts --no-plugins` (use the complete PHP 8.5 fixture INI when Composer requires PHP 8+; the manifest fixes PHP 7.4.33). The default PHP 7.4 command selects `tests/Compatibility/Laravel6/bootstrap.php` and its own vendor. The candidate flag selects only the installed candidate test bootstrap/autoloader (currently Laravel13; the Laravel12 directory name is retained) and is propagated to every worker. Workers inherit PHP_BINARY and the complete selected ini; command-line -d overrides are not inherited. The ignored php85-fixture.ini enables the portable PHP8.5.11 GD, zip, pdo_mysql and normal application extensions without modifying the system configuration. See [runtime preparation and replay](../../../docs/mysql-concurrency.md).

The server is fixed to MySQL8.4 on 127.0.0.1:13316, database dujiaoka_concurrency_fixture, user dujiaoka_fixture. No shop environment file or connection override is used. Explicit enable, the exact fixture_marker value and observer data-directory checks precede table changes. [The standalone initializer](../../mysql-fixture-bootstrap.php) validates the existing fixture. Only fifteen mc_ fixture tables are rebuilt; all seven actual migration up() methods run with that prefix, and all tables must be InnoDB. The marker is read-only. A coordinator file lock prevents overlapping resets.

Each race starts independent PHP workers. The coordinator holds target rows and every worker connection must enter InnoDB LOCK WAIT. It checks all waits again after a further 500ms held interval before release. INNODB_TRX has a 100ms idle-before-refresh cache; its polling interval is 150ms rather than the generic 20ms file-gate polling interval. Failure diagnostics contain only connection IDs/states, never SQL text. Both initial/final wait counts, polling interval and worker outcomes are retained under ignored tests/.runtime/mysql-concurrency.

The original eighteen groups cover payment/card/coupon idempotency, expiry/late-payment races, outbox publication/delivery leases, immutable quote contention, Stripe/PayPal create/inbox/reconciliation/capture leases, selection exclusion and interleaved independent binding inserts. Provider requests are local substitutes, with transaction-zero network and exact request/key checks. Real order/card/sales/coupon and claim implementations execute.

Fifteen further groups exercise the actual common receiptGuard and completedOrder transaction. Workers load order/gateway snapshots before ready. After every lock wait is observed, the coordinator mutates the held order or gateway row and commits: method, route, three merchant fields, price, pay_id and gateway deletion must stop both receipts without delivery. Other groups require closed-gateway recovery, expired-order manual handling without stock consumption, both modern binding exclusions, same-reference idempotency, different-reference exclusion and preserved string0. The persisted trade reference must match the sole accepted worker's requested reference, never an empty value or the loser's reference.

The final three groups invoke the actual v1 PaypalPayController, PaypalPaymentsClient and frozenUsd implementation. Both real initial quote reads finish before HTTP GET handlers park behind a second file gate. The coordinator then acquires the order lock and releases those GET responses, so the observed waits belong to execution reservation or fulfillment. Instrumentation counts quote reads without replacing their behavior. A single execute POST must observe the committed marker through an independent limited-user PDO connection and wait for the other worker to exit before returning503. Still-created retries only GET and checkout reentry creates no replacement payment. Approved/completed-Sale GETs then deliver one real card and one sales increment. The three phases total one execute and six business GETs, all outside transactions.
